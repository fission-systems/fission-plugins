`docs/PLAN_M2.md` 7절 2번의 산출물. 파인튜닝 스크립트는 아직 없고, 이 폴더는 데이터를 만든다.

```bash

python3 training/audit_dataset.py <출력 폴더>                       # audit.json, nearest_train_jaccard.json
```

기본값은 arm64, O0/O1/O2, 시드 20261110. 기존 폴더는 덮어쓰지 않는다. 지금 만든 세트는
`/Users/sjkim1127/fission-plugins-corpus/d0-v1`(38MB, 리포 밖)에 있고 입력 코퍼스(`matrix2`)와 각 파일의 sha256이
`manifest.json`에 있다.

## 예시 형식

한 줄이 JSON 한 개(`<split>.jsonl`). **학습 손실은 `completion`에만 건다.** `prompt` 끝은 줄바꿈이다.

```
prompt:      Fission pseudocode:
             ```c
             <의사코드>
             ```
             Variables:
             - param_1: long long (arg 0)
             - local_c: int (stack)
             Restore the source names for: param_1
             Edit list (JSON):
completion:  {"renames": {"param_1": "list"}}
```

그 밖의 필드: `id`, `split`, `group`, `project`, `license`, `arch`, `opt`, `address`, `name`, `targets`,
`function_name_masked`, `n_tokens`(토크나이저별 프롬프트+정답 토큰 수).

**타깃(정답을 요구하는 변수)은 DWARF와 `unique`로 정렬된 변수뿐이다.** `shared`/`none`/`multi-candidate`
변수는 정답이 없으므로 프롬프트의 변수표에는 나오지만 타깃에는 넣지 않아 손실이 걸리지 않는다. 모델은 요청받은
변수만 답한다. 따라서 **모델이 "이름을 붙이지 않음"을 학습하지는 않으며**, 추론 시 어떤 변수를 요청할지와 확신이
낮은 답을 버리는 규칙은 호스트의 몫이다(PLAN_M2 5절의 범위-정밀도 곡선). 모든 정답 편집은 `apply_edits`로 검사해
적용기가 거부할 항목(중복 새 이름 등)을 뺐다.

함수 이름 가림: 학습 예시의 약 50%는 의사코드 안의 자기 함수 이름을 `FUN_<주소 8자리>`로 바꿨다(함수 단위로 결정).
평가 분할(`val`, `test`, `xproj`)은 가리지 않은 파일과 가린 파일(`*-masked.jsonl`)을 따로 둔다. `FUN_<주소>`가
Fission이 숨은 함수에 쓰는 실제 이름과 같은지는 확인하지 않았다(가정). 호출하는 다른 함수 이름은 가리지 않는다.

## 분할

함수 단위가 아니라 **그룹 단위**다. 식별자와 숫자를 지운 토큰 모양이 같은 함수(`isl_*_list_*` 같은 템플릿
복제)는 모든 빌드에서 한 그룹이고, 그룹은 통째로 한 분할에 간다. 그룹 크기가 100을 넘으면 학습으로 보낸다
(가장 큰 그룹이 1,638개 함수). capstone은 학습하지 않는 `xproj`(다른 프로젝트) 시험 세트다.

| 분할 | 예시 | 함수 | 그룹 | 타깃 변수 |
|---|---:|---:|---:|---:|
| train | 11,568 | 6,669 | 3,240 | 31,654 |
| val (가림 없음 / 가림) | 1,220 / 1,219 | 715 | 420 | 4,086 |
| test (가림 없음 / 가림) | 1,081 / 1,079 | 635 | 416 | 3,429 |
| xproj, capstone (가림 없음 / 가림) | 356 / 356 | 166 | 125 | 925 |

학습 토큰은 Qwen3.5 토크나이저로 743만(예시당 평균 643), Qwen2.5-Coder로 680만(평균 588). 프롬프트와 정답을 합쳐
**2,048토큰을 넘는 예시는 뺐다**(2,501개, 만든 예시의 약 13%). 긴 함수가 학습과 평가에서 빠졌으므로 결과는 짧은
함수 쪽으로 편향된다. 같은 함수의 빌드 간 동일 프롬프트 1,684개는 중복으로 제거했다.

## 감사 결과 (`audit.json`)

- 분할 사이 **그룹, 함수 이름, 정확히 같은 토큰 모양의 겹침은 val/test에서 0**이다.
- 그러나 근사 복제는 남는다. 토큰 4-gram Jaccard로 가장 비슷한 학습 함수를 찾으면 val/test 함수의 **13~15%가
  0.8 이상**이고 중앙값은 0.5다(xproj는 중앙값 0.31, 0.8 이상 3%). 예시별 값은 `nearest_train_jaccard.json`에 있어
  평가 때 유사도 구간별로 나눠 보고할 수 있다(isl 평가 행 2,301개 중 1,015개가 0.5 미만).
- **정답 이름 어휘가 거의 닫혀 있다.** val/test 정답 이름의 97~98%가 학습 정답에 이미 나오고, 상위 20개 이름(`i`,
  `space`, `list`, `user`, `ctx`, `n`, …)이 정답의 43~48%를 차지한다. capstone(xproj)은 35%만 학습에 나온다.

## 이 세트로 말할 수 있는 것과 없는 것

- isl 안의 val/test 점수는 **같은 프로젝트의 이름 관습과 근사 복제 덕에 낙관적**이다. 파이프라인이 맞게 학습되는지,
  학습 곡선이 어떤 모양인지 보는 용도다. 일반화 주장에는 쓰지 않는다.
- 프로젝트가 달라지는 신호는 xproj뿐이고 규모가 작다(함수 166개, 그룹 125개, 타깃 925개).
- 레이블은 arm64 정렬 규칙(손으로 87쌍 확인, 85 정확 / 2 부분 정확)에 기대고 x86-64는 포함하지 않았다
  (`--archs arm64,x86_64`로 추가 가능, 정렬 검증 전). O1/O2는 `unique` 변수만 남아 레지스터 변수가 적다.
- 정답은 "원본 소스 이름"이지 "좋은 이름"이 아니다.

## 학습: `finetune.py` (M2a)

```bash
python3 training/finetune.py --model Qwen/Qwen2.5-Coder-1.5B --data <d0 폴더> --out <새 폴더> --functions 3000 --seed 1
```

transformers + peft만 쓰는 LoRA 학습이다(r=16, alpha=32, 모든 선형층, lr 2e-4 코사인, 2에폭, AdamW).
`pip install peft`가 필요하다. 후보 모델 3개를 같은 데이터와 같은 값으로 돌리려고 모델 이름만 바꾸게 했다.

- **손실은 정답(completion)과 EOS에만** 건다. 프롬프트 라벨은 -100. 최적화 한 번마다 합산 손실을 그 묶음의
  정답 토큰 수로 나눈다(시퀀스 수가 아니다).
- **학습 함수 수 곡선:** `--functions N`은 시드 고정 순서(`--subset-seed`)의 앞 N개 함수다. 1천 ⊂ 3천 ⊂ 전체
  (중첩)이고, 고른 함수의 모든 빌드·가림 변형을 함께 쓴다. **D0 학습 분할은 6,669개 함수뿐이라 PLAN_M2의 9천은
  나오지 않는다.** 곡선은 1천 / 3천 / 6.7천(전체)이고, 9천 이상은 D1(프로젝트 추가)이 있어야 한다.
- 검증 손실을 `--eval-every` 단계마다 고정 부분집합(`--val-examples`, 기본 함수 600개의 가림·가리지 않음)에서
  재고 가장 낮은 어댑터를 `<out>/best`, 마지막을 `<out>/final`에 저장한다. 시험 세트는 이 스크립트가 읽지 않는다.
  손실이 가장 낮은 체크포인트와 이름 정확도가 가장 높은 체크포인트가 다를 수 있다(forge에서 NLL 선택이 틀렸던
  경험). 최종 비교에는 둘 다 낸다.
- 출력: `log.jsonl`(단계별 학습·검증 손실), `run.json`(인자, 데이터 sha256, 단계 수). 기존 폴더는 덮어쓰지 않는다.
- 배치는 길이가 비슷한 예시를 묶어 패딩 포함 토큰 수(`--batch-tokens`, 기본 8192)로 제한한다.

### 확인한 것과 하지 않은 것 (2026-11-10)

- 단위 테스트(`tests/test_finetune.py`): 함수 부분집합의 중첩, 변형 유지, 라벨 마스크, 배치 예산, 패딩. 통과.
- Mac(MPS, bf16)에서 아주 작은 실행(함수 20개, 4단계)을 Qwen2.5-Coder-1.5B로 돌려 초기 검증 손실 계산, 학습 단계,
  로그가 도는 것을 확인했다. 단계당 약 110초(4천 토큰 두 묶음, 다른 작업이 CPU를 쓰는 중)라 **로컬 학습은 현실적이지
  않다. Colab GPU가 필요하다.** 저장(best/final)까지는 이 실행에서 확인하지 못했다(시간 제한으로 중단).
- **Qwen3.5(하이브리드)는 로컬에서 학습 단계를 끝내지 못했다.** 순전파는 된다(0.8B, 시퀀스 512에서 약 2초). 그러나
  `chunk_gated_delta_rule`과 `causal_conv1d`가 순수 PyTorch 대체 구현으로 돌아가고, 역전파 한 단계가 4분을 넘겼다.
  CUDA에서는 `flash-linear-attention`과 `causal-conv1d`를 깔면 빠른 커널이 쓰인다고 transformers가 안내하지만
  **설치와 속도는 Colab에서 확인한 값이 아직 없다.** 설치가 안 되면 Qwen3.5 두 후보의 학습 비용이 크게 늘 수 있다.
- LoRA 어댑터를 병합해 GGUF로 변환하고 양자화한 뒤의 정확도는 아직 재지 않았다.
