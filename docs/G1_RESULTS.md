## 세 후보 비교 (같은 의사코드 텍스트 150개, 145,574바이트)

세 모델 모두 변환, Q8_0·Q4_K_M 양자화, `llama-server` 생성이 성공했다(Qwen2.5-Coder-1.5B와 Qwen3.5-0.8B-Base는
라이선스 Apache-2.0을 HF 모델 정보로 확인하고 가중치를 받아 같은 절차로 진행).

| 모델 | Q4_K_M / Q8_0 크기 | 토큰 수(같은 텍스트) | perplexity f16 / Q8_0 / Q4_K_M | 비트/바이트 f16 → Q4_K_M | Q4 손실 | Metal 생성 tok/s (Q4_K_M) |
|---|---|---:|---|---|---:|---:|
| Qwen2.5-Coder-1.5B | 0.99 / 1.65GB | 44,741 | 2.853 / 2.854 / 2.904 | 0.465 → 0.473 | +1.8% | 162 |
| Qwen3.5-2B-Base | 1.31 / 2.08GB | 49,403 | 2.810 / 2.810 / 2.838 | 0.506 → 0.511 | +1.0% | 115 |
| Qwen3.5-0.8B-Base | 0.54 / 0.83GB | 49,403 | 2.986 / 2.985 / 3.059 | 0.536 → 0.547 | +2.5% | 184 |

읽는 법:
- perplexity는 토큰당 값이라 토크나이저가 다른 Qwen2.5와 Qwen3.5 사이에서는 비교할 수 없다. 비교용으로
  `ln(PPL) × 토큰 수 / 바이트 / ln 2`로 환산한 비트/바이트를 넣었다(근사: 청크 첫 토큰과 끝 조각을 무시).
  같은 의사코드를 모델링하는 능력은 Coder-1.5B가 가장 좋다(0.465), 다음 Qwen3.5-2B(0.506), 0.8B(0.536).
  **이는 의사코드 언어 모델링 지표일 뿐 이름 복원 정확도가 아니다.** 파인튜닝 후 순위가 같을지는 모른다.
- Qwen2.5 토크나이저는 같은 텍스트를 Qwen3.5보다 약 10% 적은 토큰으로 인코딩한다(44.7천 대 49.4천). 같은
  함수를 더 짧은 시퀀스로 학습·추론하므로 비용에 약간 유리하다.
- 4비트 손실은 모델이 작을수록 크다(0.8B +2.5%, 2B +1.0%, Coder-1.5B +1.8%). 모두 베이스 모델 기준이고
  쌍체 검정은 하지 않았다(표준오차는 perplexity의 약 ±1.3%).
- 생성 속도는 GPU(Metal)만 신뢰한다. CPU 전용(`-ngl 0`) 측정은 Rust 빌드(`rustc`)가 동시에 돌아 로드 평균이
  28~38인 상태에서 같은 모델이 1.5~100 tok/s로 흔들려 쓸 수 없었다. 위 2B의 CPU 전용 73 tok/s도 같은 이유로
  참고용이다. 사용자 기기와 같은 조건의 CPU 전용 지연은 부하가 없을 때 다시 잰다.
